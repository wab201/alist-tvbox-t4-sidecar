# AList-TVBox T4 Sidecar

将已授权的 AList-TVBox（AT）订阅和本地 Python/JavaScript 插件转换为 T4 接口，
供 FM 影视、TVBox 等客户端使用。以独立容器运行，不修改 AT 的数据库、插件或 Web 页面。

当前版本：**0.3.16**。

- [使用指南](USAGE.md)：导入影视、上传和管理插件、网盘播放、兼容检测与故障排查。
- [部署指南](NAS_DEPLOYMENT.md)：Docker/NAS 部署、源码构建、反向代理、升级与备份。

## 播放稳态能力

- 每个出口仅提供一个订阅地址。正文始终是标准 T4，JAR 与原生组件移入可选发现描述；
  未发现、下载或自检失败、会话过期时，原地址继续返回标准 T4，不需用户切换地址。
  组件发现是本项目扩展协议；未适配该协议的客户端仅使用标准 T4，不代表原版 FM 会自动加载。
- 优化方向调整为起播、拖动、暂停恢复和断流补接，不承诺带宽叠加或稳定提速。
- 增强组件短暂复用文件元数据，减少连续拖动时的重复探测；长时间停止读取后按精确偏移重新直连。
- 瞬时故障先重试一次直连，仍失败再尝试一次服务器补接；保持文件身份校验，不缓存视频正文。
- 纯 T4 和增强模式均按实际播放列表，为内置、Python、加密 secspider、JS 和官方远程 T4
  插件预热同线路紧邻下一集，片单选源后也走真实插件；不再限定 AList/小雅或数字文件 ID。
  复用原运行时、忙时跳过，不跨线路、不批量解析、不预下载媒体；状态型插件代理保留按需取链。
  限制和日志见[使用指南](USAGE.md#播放稳态优化)。
- 已通过服务端与 HTTP/JVM 合同测试，客户端组件发现适配、真机解码和长播仍待验收。

## 其他已支持能力

- 多个独立 T4 出口支持创建、重命名、停用和删除，自动生成可复制的订阅地址。
- 每个出口独立设置插件启停、白名单和黑名单，支持筛选与批量选择；片单搜源同步遵守出口规则。
- 多客户端并发共享原有 Worker，不重复启动插件运行时，不增加 Token；客户端读播入口支持浏览器跨域访问。
- 出口设置保存在原数据卷，无需新增端口、容器或环境变量；默认订阅地址保持不变。

- 片单卡片可由配套飞牛扩展直接打开原生搜源结果，选源后进入详情、季集和播放。
- 详情 ID 与请求追踪分离，影片身份保存在数据卷，减少重启后旧卡片失效。
- 全量兼容检测逐项列账，区分定向抽样和整份订阅通过；隔离探针不再误测生产端口。
- 不打包依赖私有部署的自定义插件及其配套模块，通用插件仍按原合同运行。
- 片单搜源不再固定截取前 6 个插件；默认覆盖全部可搜索插件，可在管理台勾选指定范围。
- 配套飞牛扩展可分批取得片单搜源结果，首批先显示，滚动分页复用同一任务；
  新结果只追加、不重排已显示内容。每次取页最多等 2 秒，总搜源仍限 25 秒、3 路并发，
  不足一页时可用原生「继续搜索剩余来源」目录接续。无需修改官方客户端。
  增量会话最多 8 份，每份最多 500 条、768 KiB，完成后空闲 120 秒回收；
  该能力需同时升级 Sidecar 0.3.11 和飞牛扩展 0.2.25-t4.6，
  不代表预算内所有插件都已搜索完成。
- 大订阅支持按插件名/ID 筛选、全选和清空，便于一次选出常用来源。
- 片单搜源识别“2024 / 内地”等复合年份，不再误过滤同名同年份的有效片源。
- 按订阅顺序搜源、最多 3 路并发，25 秒内汇总已完成线路；超时不再启动后续任务。
- 搜源选择保存在 Sidecar 数据卷，重启继续生效，不修改 AT 订阅；详情不预解析播放地址。
- 修复盘搜分组搜索结果在 T4 客户端点击后无法取得播放地址：自动展开缓存目录，保留网盘标识和分页。
- 搜索只读取资源卡片，选中后才取得详情与播放地址，不预解析全部分享。
- 搜索和浏览插件空闲 3 分钟后分批退出，避免全源搜索留下大量常驻进程。
- 回收后点开旧搜索结果，按需恢复对应浏览上下文；详情、播放、动作及代理实例保留。
- Docker/NAS 日志页直接显示脱敏请求、插件、播放和回收事件，每分钟报告内存及 Worker 数。
- 新增资源诊断接口；查看日志、健康和 Web 页面不再推迟空闲整理。

## 功能

| 功能 | 说明 |
| --- | --- |
| 统一订阅 | 自动读取 AT 订阅，汇总可执行插件和本地插件，提供 `/t4/config.json` |
| 多 T4 出口 | `/t4/profiles/{出口ID}/config.json` 提供独立地址，出口级插件白名单/黑名单与停用状态持久保存 |
| 中文管理页面 | 独立 `/t4/` 入口，自动生成可复制的完整订阅和单插件 FM 地址 |
| AT 内置源 | 对接 Bilibili、我的追更、我的云盘、AList、片单、直播等原生服务 |
| AT 插件 | 支持 ATVP raw Python、官方格式加密插件，以及动态 loader/keyring 配置 |
| 官方远程插件 | 识别 AT 官方 T4 插件描述符，转发至 AT 执行，不重复启动本地插件 |
| 自定义插件 | 上传标准 Python、Sidecar JavaScript 或包含依赖文件的 ZIP，自动注册 |
| 插件管理 | 删除、重命名、排序、刷新运行实例、首页检查和复制地址，设置持久保存 |
| 网盘服务端通路 | 可选服务端代理和 AT 内网回源，复用 AT/PowerList 已有网盘配置 |
| 媒体网络交付 | 普通直链携带请求头交给客户端；支持 HLS、内联 DASH 和必要代理转发 |
| 客户端可选增强（开发中） | 同一订阅可选发现轻量 JAR，本地代理自检通过才启用；有限文件直连断流补接，未确认时保持普通 T4 交付 |
| 兼容检测 | 批量检查首页、分类、搜索、详情、图片、取链及媒体字节，导出结果 |
| 播放诊断 | 查看请求关联日志、插件错误、网络状态和耗时，导出脱敏日志 |
| 运行资源 | Linux Worker 共享基础库；空闲浏览实例分批退出，冷 ID 和浏览上下文转存临时磁盘 |

## 使用

1. 按部署指南启动容器，只需配置 AT 完整订阅地址。
2. 打开 `http://NAS_IP:8765/t4/`。
3. 点击“复制影视订阅地址”，导入影视客户端的点播配置。
4. 在影视中选择站点使用；上传本地插件后刷新影视配置即可。

无需额外配置 Gateway Token、单插件参数或手工拼接 JSON。AT 原有授权仍由上游负责。

## 适用范围

- 服务端负责订阅读取、爬虫运行、网络请求和结果交付；客户端负责视频解码与播放。
  不转码、不重封装，也不增加额外分片下载层。
- AT 推送保留原生客户端实现，需要支持 JAR 的客户端；通过可选组件描述提供，
  不进入标准订阅正文。未适配组件发现的客户端不具备此原生能力。
  WebHome 等页面入口不转换为点播插件。
- Python/JS 插件需要符合支持的运行合同并具备配套依赖，不能保证任意脚本上传即用。
  官方远程插件的可用能力取决于对应 AT 版本。
- 网盘代理不保证比直连更快；当前不承诺全插件兼容、原客户端性能等价或真机长播全部通过。
- 多出口只隔离订阅导出范围和请求策略，共享同一容器的插件 Worker、缓存和上游订阅；
  不会复制插件运行时，也不会把不同客户端的播放流合并。
- 管理入口可执行上传的插件，只应提供给可信用户。可选组件描述包含原生 AT 推送所需授权，
  不要公开分享；远程访问使用现有 VPN 或有访问控制的反向代理。
